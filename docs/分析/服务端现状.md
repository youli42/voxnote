# 服务端现状（v2 默认后的功能盘点）

> 2026-10-27。检查对象：`server/voxnote_server/`（v1 + v2 两套）、`server/web/v2.html`、`server/web/index.html`。
> 结论先说：**功能没有从仓库删除**；是默认入口从 v1 控制台切到了 v2，而 v2 只实现了 V1 范围的子集。
> v1 控制台与 v1 API 仍完整保留在 `/legacy` 与 `/api/v1/*`。

## 1. 当前运行结构

| 入口 | 内容 | 状态 |
| --- | --- | --- |
| `/` | v2 控制台（`server/web/v2.html`） | 默认；功能较少 |
| `/legacy` | v1 控制台（`server/web/index.html`） | 完整保留，可继续用 |
| `/api/v2/*` | v2 设备同步 + 控制台 API（34 条路由） | 默认启用 |
| `/api/v1/*` | v1 旧 API（46 条路由） | 仍挂载，手机切 v2 后基本不用 |
| `VOXNOTE_V2=0` | 回滚到 v1 控制台/API | 可用 |

数据库：v2 用 `data/voxnote-v2.db`；v1 旧库 `data/voxnote.db` 原样保留。

## 2. v2 API 现有能力（34 条）

- 同步：`/sync/changes`、`/sync/manifest`、`/sync/upload`、`/sync/ops`、`/sync/conflicts`、`/sync/conflicts/{id}/resolve`
- 记录：list/detail/audio/transcript/attempts/active-attempt/export/jobs/transcribe
- 修订：`GET/POST /records/{id}/edits`
- 引擎：`GET/POST/PATCH/DELETE /engines`、`/engines/{id}/probe`
- 队列：`GET /jobs/{id}`、`GET /records/{id}/jobs`
- 运维：`/settings`、`/storage`、`/backups`、`/cleanup`、`/diagnostics`
- 控制台：`/console/pair`、`/events`（SSE）
- 健康：`/health`

## 3. v2 控制台现有页面

1. **记录库**：列表（标题/状态/时长/rev/更新时间）、标题/ID 搜索、详情（基本信息、生效稿只读、修订 JSON、导出 md/srt、WaveSurfer 播放/波形）
2. **冲突**：列表 + 选本地/服务器
3. **引擎**：列表、新增、启停/删除（页面只做了新增 + 列表）
4. **存储与诊断**：配对二维码、存储 JSON、备份、清理预览/执行、诊断 JSON、保留策略

## 4. 与 V1 控制台/计划的差距

| 功能 | v1 | v2 | 判断 |
| --- | --- | --- | --- |
| 工作台/统计（今日新同步、队列、待修订、音频库） | 有 | 无 | **缺** |
| 记录库筛选（状态/分类/未分类/仅音频） | 有 | 仅标题/ID 搜索 | **缺** |
| 批量归类 | 有 | 无 | **缺**（V1 计划后置批量，但 v1 已有） |
| 详情改名/分类/标记/删除 | 有 | 无（API 只有设备 ops） | **缺** |
| 逐句修订 | 有（PATCH/DELETE segment） | 只有只读稿 + 修订 JSON | **缺** |
| 版本/尝试 diff | 有（versions） | 有 attempts/active-attempt API，无 UI/diff | **部分** |
| 任务卡（进度/失败/重试/取消） | 有 | 只有按记录查 job；无队列页/重试/取消 | **缺** |
| 实时转写进度 | 有 | SSE 只推全局 rev，无任务事件 | **部分** |
| 冲突处理 | v2 协议 | 有页面 | **有** |
| 导出 md/srt | 有 | 有 | **有** |
| 音频播放/波形 | 有 | 有（WaveSurfer） | **有** |
| 设备/令牌/最后同步 | 有（pair-info/reset-token） | 只有二维码，无设备列表/令牌轮换 | **缺** |
| 存储/备份/清理/保留 | 有 | 有 | **有** |
| 引擎管理 | 有（v1 模型/ASR） | 有 CRUD/probe，页面只做新增 | **部分** |
| 设置重组（地址簿等） | 有部分 | 只有保留策略 | **部分** |
| AI 助手 | 有 | 无 | 按 V1 计划**不在 V1 范围** |
| 本地模型/whisper 下载 | 有 | 无 | 按 V1 计划**不在 V1 范围** |
| 录音流/批量 review/导入音频 | 有 | 无 | 按 V1 计划**不在 V1 范围** |

## 5. v2 API 层缺的接口（补齐控制台所需）

- `GET /stats`：工作台统计
- `GET /jobs`（队列列表）+ `POST /jobs/{id}/retry|cancel`
- 管理端记录变更：`PATCH /records/{id}`（标题/分类/标记）、`DELETE /records/{id}`（墓碑）
- 句级修订：明确“改文本/删句/恢复”的接口（现在只有追加 edit）
- `GET /records/{id}/versions|diff`：尝试对比
- `GET /devices`、`POST /tokens/reset`/pair-info
- `/records` 增加 `q/status/cat` 筛选参数
- 导入音频（v1 有 `/records/upload`；v2 无）
- SSE 增加 job/progress 事件（现在只有 record changes 的 rev）

## 6. 测试与风险

- v2：64 个 unittest 全过；e2e 33 项；5 个验收脚本；恢复/回滚演练通过。
- 缺口：**控制台 UI 没有自动化测试**，上述缺失功能也没有 e2e 覆盖；SSE 只验证了连接/刷新。
- 兼容风险：`/legacy` 与 v1 API 依赖 v1 库；手机切 v2 后 v1 控制台看到的是旧数据，两边不会自动合并。

## 7. 建议

**P0（恢复日常可用）**
1. 记录库筛选 + 详情编辑（标题/分类/标记/删除）
2. 逐句修订 + 版本/尝试切换与 diff
3. 任务队列页 + 任务卡进度/失败/重试/取消
4. 工作台统计
5. 同步与设备页（设备列表/最后在线/令牌轮换/配对）

**P1**
- 批量归类、导入音频、整库导出；SSE 增加任务事件。

**P2（按 V1 计划后置）**
- AI 助手、本地模型管理、录音流/批量 review：继续留在 `/legacy` 或后续版本。

> 短期如果只想“功能都在”，可以把 `/` 临时指回 v1 控制台；但那会推翻 v2 默认切换。
> 更合理的路径是按 P0 把 v2 控制台补到 V1 计划要求的 W4 完成度。
