# 数据契约 v1

原则：**文件是真相，数据库只是索引**。整个目录必须能直接拷走、重建、被脚本消费，
所以格式只用 UTF-8 文本（JSON / JSONL / Markdown），不依赖 SQLite。

本文写的是**目标形态**：列出的对象与规则是契约要求的；哪些已经落地、哪些还没有，
看 [README 的当前状态](../../README.md#当前状态)。

## 1. 目录

```
/sdcard/s1rec/
  index.jsonl                        每场一行摘要（供脚本与人读）
  sessions/<yyyyMMdd_HHmmss>_<sid>/
    record.json                      会话元数据
    segments.jsonl                   逐句事实（机器派生，可重放）
    edits.jsonl                      编辑与标记（append-only，永不覆盖）★
    transcript.md                    导出物（可删可重建）
  engine/<sid>/<engine_id>.<rev>.jsonl   引擎原始回包（重跑与审计）
  archive/<yyyyMMdd>/tmlog.tm.*        原始输入快照（防清数据/刷机）
```

`<sid>` 是 10 位秒级会话号；目录名前缀是本地时间 `yyyyMMdd_HHmmss`，仅供人读。
同一场录音的不同载体（自录音频、旁车文稿、外部导入）都按这个时间前缀归并。

## 2. 标识符

| 对象 | 规则 | 性质 |
| --- | --- | --- |
| `sid` | 10 位秒级时间戳；`sid<=0` 视为脏数据丢弃 | 稳定 |
| `segId` | 会话 + 起止时间 + 归一化文本的哈希（取前 16 位） | 可重算 |
| `markId` | `sid` + 时间点 + 类型 | 可重算 |
| `editRev` | 每台设备单调递增的整数 + 设备标识 | 排序用 |

归一化文本指：去首尾空白、内部连续空白折叠为单个空格，不做其他改写。
重放同一输入必须得到同一批 `segId`——这是编辑能稳定挂接、同步能去重的前提。

## 3. 对象

| 对象 | 用途 | 性质 |
| --- | --- | --- |
| `index.jsonl` | 每场一行摘要：会话号、开始时间、时长、模式、状态、句数、音频位置、目录 | 可由事实层重建 |
| `record.json` | 会话元数据：录音参数、时长、状态、错误计数、音频位置、摘要、说话人轴、产出方 | 机器派生 + 少量人工字段 |
| `segments.jsonl` | 逐句事实：最终句（带发言人归属 `spk`）、可选的中间态、说话人切换 | 机器派生，可无限重放 |
| `edits.jsonl` | 编辑与标记：改文本、拆分、合并、删除、打星、备注 | **只追加，永不回写事实层** |
| `transcript.md` | 人读的导出物 | 随时可删可重建 |

合成规则：`segments` 先按 `editRev` 升序应用全部 `edits` 得到"当前视图"；
永不回写 `segments.jsonl`，因此重放日志不会丢编辑。

**删除**：对导入来源的场次，"删除"是意图层的墓碑（屏蔽）——它只让该场不再进入视图，
重放事实层也无法让它复活；厂商的原始录音与日志永不改写。自录音频的删除是真删文件，
属于用户对归档层的显式操作，不产生墓碑。

**说话人 `spk`**（schema v2 起，来源侧提供时）：0 基整数，是来源引擎在本会话内给出的身份编号，
**只在本 `sid` 内稳定**，跨会话不可比（同一人换个会话可能是别的号）；`-1` 表示该来源没给说话人数据，
必须与"发言人 0"区分，不得默认填 0。`record.json` 以 `speaker_axis` 标明本场有无此数据、
`speakers[]` 给出 `tag`/`gender`/句数；`gender` 原样透传来源，语义不在本契约内解释。

## 4. 状态枚举

| status | 含义 |
| --- | --- |
| `ok` | 有正文 |
| `summary` | 仅有摘要 |
| `error` | 有声但识别失败 |
| `audio_only` | 有录音、无正文无摘要 |
| `empty` | 无任何内容（通常不展示） |

**不允许"看起来正常的空稿"**：任何空白都必须落到上表某一项，并在界面显式呈现。

## 5. 幂等与重放

- 全量重扫输入 = 幂等：相同输入重复解析，`segId` 与内容一致；
- 增量导入必须按**文件身份**而非文件名记录游标：厂商日志会轮转改名，
  按名字记偏移会导致整文件重放；
- 上报行（含 `%22` / `json:`）先丢弃：它们是统计上报，内含锚点字样，会造成重复计数。

## 6. 兼容

- `schema` 版本随会话元数据一起落盘；升级时写迁移脚本，保留旧文件 30 天；
- 新增字段只加不删；删除字段先标记 `deprecated` 一个版本；
- 时间一律毫秒整数（与录音内时间轴对齐），展示层再格式化。
