# 控制台补充接口（v2）

> 2026-10-27。给「记录库/详情/任务/设备」补齐的接口契约。
> 全部挂在 `/api/v2` 下，鉴权沿用 `Depends(auth.require_device)`（Bearer 设备令牌），单用户 V1 不做角色区分。
> 实现位置：`server/voxnote_server/v2/`；控制台：`server/web/v2.html`。

## 1. 统计

`GET /stats`

```json
{
  "records": 123, "records_today": 5, "deleted": 2,
  "audio_bytes": 12345678, "audio_hours": 3.4,
  "jobs": {"queued": 0, "running": 1, "failed": 2, "done": 40},
  "edited_records": 7, "attempts": 55,
  "devices": 1, "last_sync_at": 1793000000000
}
```

## 2. 任务队列

`GET /jobs?state=&limit=50`

- `state`：`all`（默认）| `queued` | `running` | `failed` | `done`；`running` 同时包含 `transcribing`。
- 返回：

```json
{"jobs": [{"id": 1, "record_id": "…", "record_title": "…", "engine": "…",
           "source": "hub", "language": "zh", "state": "failed", "stage": "asr",
           "progress": 0.4, "error_code": "engine_unreachable", "error_hint": "…",
           "queued_at": 0, "started_at": 0, "finished_at": 0}],
 "counts": {"queued": 0, "running": 1, "failed": 2, "done": 40}}
```

`POST /jobs/{id}/retry` → 新建一条 queued 任务并把记录状态置 `queued`，返回 `{"job_id": 新id}`。
`POST /jobs/{id}/cancel` → `queued` 直接置 `canceled`；`running` 置 `cancel_requested=1`。返回 `{"ok": true, "state": "canceled"|"requested"}`。

## 3. 记录编辑（控制台）

`PATCH /records/{id}`，body 任意组合：

- `title`: string（空串合法）
- `cat`: string 或 null
- `marks`: JSON 数组字符串（如 `"[1.5,3]"`）或数组

返回 `{"record": record_summary, "rev": 新rev}`；必须 `append_change("record", id)`。

`DELETE /records/{id}` → 墓碑：`deleted_at=now`、`rev+1`、`append_change`。返回 `{"ok": true, "rev": n}`，**不删除音频文件**。

## 4. 修订（逐句）

- `POST /records/{id}/edits`（已存在）：按 anchor 新建修订，body `{anchor_t_ms, anchor_e_ms, text, deleted}`。
- `GET /records/{id}/edits`（已存在）。
- **新增** `DELETE /records/{id}/edits/{edit_id}` → 删除该修订（恢复机器原文），返回 `{"ok": true}`。

控制台逐句编辑的做法：从 `transcript.segments` 拿到该句 `t_ms/e_ms` 作为 anchor 调 POST。

## 5. 尝试与对比

`GET /records/{id}/attempts/{attempt_id}` →

```json
{"attempt": {"id": "…", "engine": "…", "model": "…", "quality_tier": 3,
             "duration_ms": 8000, "created_at": 0},
 "segments": [{"idx": 0, "t_ms": 0, "e_ms": 2090, "text": "…", "spk": -1}],
 "is_active": true}
```

`GET /records/{id}/diff?from=<attempt_id>&to=<attempt_id>` →

```json
{"from": "…", "to": "…", "active": "…",
 "segments": [{"idx": 0, "t_ms": 0, "e_ms": 1000,
               "from_text": "…", "to_text": "…",
               "change": "same|changed|added|removed"}]}
```

按 `idx` 对齐（同一记录的多次转写句序稳定）；缺边时对应 text 为空、change 为 added/removed。

## 6. 设备与令牌

`GET /devices` → `{"devices": [{"id": "…", "name": "…", "kind": "phone",
"app_version": "…", "last_seen_at": 0, "status": "active", "created_at": 0}]}`（读 `devices` 表，空表返回空数组）。

`POST /tokens/reset` → 生成新设备令牌写入 `settings.sync_token`，返回 `{"token": "vn2-…"}`；旧令牌立即失效（手机需重新配对）。

## 7. 记录列表筛选（扩展 `GET /records`）

新增查询参数（都可选，组合生效）：

- `q`：标题或 id 模糊匹配
- `status`：`uploaded` / `queued` / `transcribing` / `done` / `failed`
- `cat`：分类值；`__none__` 表示未分类（cat IS NULL 或空）
- `has_audio`：`true` 只看有音频的
- `include_deleted`：默认 false（已存在）

返回结构不变：`{"records": [record_summary...]}`。
