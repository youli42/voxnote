# 需求与边界

> 本文只记"要什么、不要什么、卡在哪"，不记实现细节——实现随代码演进，文档只描述功能。

## 1. 目标

在设备本地完成 **录音 → 转写 → 结构化入库 → 阅读/编辑 → 同步/自动化**，
最终替代设备自带的录音 App，并能移植到其他 Android 设备。

角色变化：早期版本是"厂商日志提取器"；现在日志解析只是众多数据入口之一。

## 2. 需求分层

### R1 必须

- **不丢内容**：任何一场录音，要么有完整文稿，要么有显式失败状态（不允许"看起来正常的空稿"）。
- **结构化底座**：会话 / 逐句 / 编辑 / 标记四类对象有稳定 ID，可重算、可合并、可重跑。
- **编辑不被覆盖**：机器派生结果可无限重放；人工编辑是独立追加层，永不因重解析而丢失。
- **阅读与编辑可用**：在小屏触摸屏上完成"读一场 → 改若干句 → 存盘 → 导出"的闭环。
- **历史不锁死**：数据必须能整目录拷走 / 重建，卸载、换设备、恢复出厂都不丢。
- **真触发判定**：能回答"这次按键到底录上了没有"，并给出证据链。

### R2 应当（替代厂商 App 的前提）

- **自录**：采集、分段落盘、时长与电平、异常中断可识别。
- **可插拔转写**：自建云服务 / 本地小模型 / 外部导入 / 人工，几种后端可共存。
- **结果可重跑**：记录用了哪个后端与版本、耗时、错误；换后端或联网恢复后可对同一音频重算。
- **按键可配**：媒体键 / 焦点键 / 厂商广播 / 无障碍 / root 统一抽象，按机型保存映射。
- **可移植**：设备差异收敛到平台能力探测，上层不猜机型；跨 Android 8→15 的存储、
  后台麦克风、通知、按键差异都有降级路径。
- **离线兜底**：没有网络时本地模型也能出稿。

### R3 后续

- **同步**：先文件级（整目录可拷），再记录级（改动序号 LWW）。
- **自动化**：导出目录 + 清单文件，供 PC / 手机端 watcher 消费。
- **模型管理**：下载、校验、空间预算、删除；按网络、语言、电量、实测速度路由。

### R4 明确不做

- 抓取或改写厂商私有数据、注入其进程；
- 多端并发实时协作编辑（LWW 够用）；
- 为省资源牺牲正确性。

## 3. 跨版本硬约束

| 维度 | Android 8（本机） | 10 / 11 / 13 / 14+ |
| --- | --- | --- |
| 存储 | 一个权限读写全 `/sdcard` | 分区存储：数据进私有目录，公共目录走系统选择器，音频进媒体库 |
| 后台麦克风 | 允许 | 10+ 禁止后台采集，需要前台服务声明 |
| 通知 | 无需申请 | 13+ 需要通知权限 |
| 全局按键 | 媒体键 / 焦点键 / root | 无障碍在 14+ 才完整 |
| 安装 | — | 14+ 拒绝过老的 targetSdk |

## 4. 未决问题

1. **共存还是替代**：要不要动厂商 App（决定是否需要影子双录、是否依赖 root）。
2. **自建转写服务的形态**：短音频 REST 还是流式 WebSocket。
3. **本地模型偏好**：小模型按语言路由，还是多语种离线模型。
4. **移植目标**：设备清单与 Android 版本分布。
5. **无 root 设备**：还能拿到哪些信号。

## 5. 隐私边界

设备日志、数据库、录音、抓包一律不进仓库；解析产物只写设备本地 `/sdcard/s1rec/`；
分析中间产物一律放仓库外。
