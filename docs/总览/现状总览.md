# 现状总览（2026-10-27）

> 一份把**服务端 / 手机端 / 测试 / 计划进度**放在一起的现状整理。
> 细节见 [服务端现状](../分析/服务端现状.md)、[进度记录](../计划/进度记录.md)、[第一版行动计划](../计划/第一版行动计划.md)。
>
> 一句话：**V1 的功能骨架已经跑通，但手机端是"v1 与 v2 两套同步栈并存"的状态，服务端 v2 控制台只补了 V1 计划的一部分。**

## 1. 仓库状态

- 分支 `design/redesign-v1`，工作区干净，已推送。
- v2 默认启用：`/` = v2 控制台，`/legacy` = 旧 v1 控制台，`/api/v2/*` + `/api/v1/*` 都挂着。
- 破坏性重建：v2 用新库 `data/voxnote-v2.db`；旧库 `data/voxnote.db` 与旧录音原样保留，不迁移。
- 回滚：`VOXNOTE_V2=0` 即回到 v1 控制台/API，已演练。

| 测试 | 64 个 unittest、e2e 33 项、5 个验收脚本、备份恢复与回滚演练、性能基准全过 |

### 2.2 v2 控制台已补齐（2026-10-27）

原先 v2 控制台只有记录库列表 + 冲突 + 引擎新增 + 存储诊断，日常不可用。现已补齐：

| 能力 | 实现 |
| --- | --- |
| 工作台 | GET /stats：记录/今日/音频时长/队列四态/含修订/设备与最近同步；最近任务与最近记录 |
| 记录库 | 五维筛选：q、status、cat（含 __none__）、has_audio、include_deleted |
| 详情编辑 | PATCH /records/{id}（标题/分类/标记）、DELETE（墓碑，不删音频） |
| 逐句修订 | POST/GET /records/{id}/edits + DELETE /edits/{edit_id}（恢复原文） |
| 尝试与版本 | GET /attempts、GET /attempts/{aid}、GET /diff、POST /active-attempt |
| 任务队列 | GET /jobs、POST /jobs/{id}/retry、POST /jobs/{id}/cancel |
| 设备与令牌 | GET /devices、POST /tokens/reset（旧令牌立即失效） |
| 保留/存储 | 原有的备份、清理、保留策略、诊断 |

控制台 7 个页面：工作台 / 记录库 / 任务 / 冲突 / 引擎 / 设置与设备 / 存储与诊断，另有记录详情页。
SSE 刷新替代轮询；接口契约见 [控制台补充接口](../设计/控制台补充接口.md)。

仍未做（按 V1 计划后置）：批量归类、导入音频、整库导出；AI/本地模型/录音流继续留在 /legacy。

## 3. 手机端（关键：双栈并存）

### 3.1 已切到 v2 的部分（`dev.voxnote.v2`）

- 录音：`V2RecordService` 前台服务，锁屏/切后台不中断
- 上传与幂等：`V2Sync` → `/api/v2/sync/upload`
- 变更同步：改名/分类/标记/删除 → `/api/v2/sync/ops`，墓碑语义
- 拉取：`/api/v2/sync/changes`、`/api/v2/sync/manifest`、转写稿
- 冲突：服务端/本地冲突列表与选择
- 同步中心：诊断、引擎、备份、清理、添加引擎、连接测试
- 详情页：v2 转写按钮、v2 生效稿显示、导出 md/srt、波形播放、自动连播
- 设置页：状态/扫码配对/同步中心/立即同步/测试连接 均走 v2

### 3.2 v1 残留已清理（2026-10-27 统一完成）

手机端原先有 41 处调用走 v1 `ServerSync`（`/api/v1/sync/*`），与 v2 令牌不匹配，实际全部 401。
本轮已全部迁移到 v2，并删除 `ServerSync.java`（62KB）：

| 原 v1 能力 | 现在的实现 |
| --- | --- |
| 主「转文字」按钮 | `POST /api/v2/records/{id}/transcribe`（带云 API 隐私提示） |
| 列表同步状态 | `V2Status.of()`：按 v2 本地库推导（待上传 / 已同步 / 异常） |
| 云端取音频 | `V2Audio`：Bearer 下载 `/api/v2/records/{id}/audio`，落私有目录并并回卡片 |
| 重试上传 | `V2Sync.syncAsync()`（outbox 失败项自动重试） |
| 录完自动上传 | `V2Sync.syncAsync()` |
| 前台实时轮询 | 每 6 秒 `V2Sync.syncAsync` + `applyV2ServerMeta()` 把服务器元数据并回本地 |
| 服务器引擎选择 | 移除；引擎在控制台 / 同步中心配置 |
| 配对判断 / 设备名 / 状态行 | 改为 `V2Sync.hasServer` / `Build.MODEL` / `v2Status()` |

验证：Android 构建通过（APK 380KB → 364KB），服务端 64 单测与 e2e 冒烟全过。

## 7. 风险

- **双栈并存是当前最大风险**：任何"看起来该生效"的操作可能走错通道，且失败只表现为状态不动。
- 控制台 UI 无自动化测试，缺的功能也没 e2e 覆盖。
- `/legacy` 与 v1 API 依赖 v1 库；手机切 v2 后，v1 控制台看到的是旧数据，两边不会自动合并。
