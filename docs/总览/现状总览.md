# 现状总览（2026-10-27）

> 一份把**服务端 / 手机端 / 测试 / 计划进度**放在一起的现状整理。
> 细节见 [服务端现状](../分析/服务端现状.md)、[进度记录](../计划/进度记录.md)、[第一版行动计划](../计划/第一版行动计划.md)。
>
> 一句话：**V1 的功能骨架已经跑通，但手机端是"v1 与 v2 两套同步栈并存"的状态，服务端 v2 控制台只补了 V1 计划的一部分。**

## 1. 仓库状态

- 分支 `design/redesign-v1`，工作区干净，已推送。
- v2 默认启用：`/` = v2 控制台，`/legacy` = 旧 v1 控制台，`/api/v2/*` + `/api/v1/*` 都挂着。
- 破坏性重建：v2 用新库 `data/voxnote-v2.db`；旧库 `data/voxnote.db` 与旧录音原样保留，不迁移。
- 回滚：`VOXNOTE_V2=0` 即回到 v1 控制台/API，已演练。

## 3. 手机端（关键：双栈并存）

### 3.1 已切到 v2 的部分（`dev.voxnote.v2`）

- 录音：`V2RecordService` 前台服务，锁屏/切后台不中断
- 上传与幂等：`V2Sync` → `/api/v2/sync/upload`
- 变更同步：改名/分类/标记/删除 → `/api/v2/sync/ops`，墓碑语义
- 拉取：`/api/v2/sync/changes`、`/api/v2/sync/manifest`、转写稿
- 冲突：服务端/本地冲突列表与选择
- 同步中心：诊断、引擎、备份、清理、添加引擎、连接测试
- 详情页：v2 转写按钮、v2 生效稿显示、导出 md/srt、波形播放、自动连播
- 设置页：状态/扫码配对/同步中心/立即同步/测试连接 均走 v2

### 3.2 仍走 v1 `ServerSync` 的部分（41 处调用，全部 `/api/v1/sync/*`）

- 列表卡片同步状态（`syncState`）、`pollLive` 实时轮询、`syncCloud`
- **详情页主"转文字"按钮**（`transcribeRemote`）
- 云端取音频（`fetchAudio`）、重试上传（`retryUpload`）
- 服务器转写引擎/asr-config 选择（设置页已隐藏入口）

### 3.3 由此产生的实际缺陷（P0）

v1 的 `/api/v1/sync/*` 校验的是 **v1 库里的 sync_token**；手机配对时存的是 v2 令牌（`vn2-…`）。
结果：上述 v1 请求**全部 401**——真机日志里持续出现 `GET /api/v1/sync/records?since=0 401`。

影响：

1. 详情页**主"转文字"按钮不可用**（只有 v2 行里的"转写"按钮能用）；
2. 列表同步状态、云端取音频、失败重试实际不生效；
3. 状态来源分裂，用户看到的信息可能互相矛盾。

## 5. 计划进度（M0–M6）

- M0 准备与备份：完成（旧录音已备份到手机与电脑，MD5 一致）
- M1 服务端契约：完成（34 条 v2 API + 契约测试）
- M2/M3 手机底座与 UI 收敛：完成主体；遗留任务卡/冲突逐项等细节
- M4 可用性补全：后台录音、导出、自动连播、备份清理完成；锁屏 10 分钟待实测
- M5 引擎与队列：完成（多引擎手动选择、不自动切换）

DoD 9 项中 **8 项已勾选**，仅剩"锁屏录音 10 分钟完整 + 来电中断可恢复"未在真机跑满。

## 6. 待办（按优先级）

1. 手机端统一到 v2：主"转文字"按钮、同步状态、云端取音频、重试、实时轮询全部改走 v2，删除 v1 `ServerSync` 依赖（否则会持续 401）。
2. 服务端 v2 控制台补 W4 核心：记录筛选 + 详情编辑 + 逐句修订 + 任务队列。

**P1 · 可用性**

3. 设置页新布局真机目测与微调；拖动波形复测。
4. SSE 增加任务/进度事件；控制台补设备与令牌页。

**P2 · 后置**

5. 批量归类、导入音频、整库导出（#2）；AI/本地模型/录音流继续留在 `/legacy`。

## 7. 风险

- **双栈并存是当前最大风险**：任何"看起来该生效"的操作可能走错通道，且失败只表现为状态不动。
- 控制台 UI 无自动化测试，缺的功能也没 e2e 覆盖。
- `/legacy` 与 v1 API 依赖 v1 库；手机切 v2 后，v1 控制台看到的是旧数据，两边不会自动合并。
