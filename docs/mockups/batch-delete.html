删除 3 场？

· 1 场自录：删除录音文件（不可恢复）
· 2 场厂商导入：仅从列表删除并屏蔽（可撤销，原始录音与日志不动）

④ 批量删除确认（混合来源）按来源分组计数、分别说明后果；执行后 toast「已删除 3 场 · 撤销」（撤销只对厂商屏蔽部分生效）。

交互方案（本稿采用）

  • 单条删除入口：卡片右上 ⋯ 菜单（删除置红）；长按卡片 = 同一菜单，也是进批量模式的快捷方式（长按直接带选中进入 ③）。
  • 左右滑不动：两个方向已被「归类」占用，删除不再抢手势。
  • 批量入口：顶栏「管理」；进入后搜索栏替换为「全选 · 已选 n/N · 完成」，筛选行保留——"筛未分类 → 全选 → 删除/归类"是主用例。
  • 底部操作栏：删除(红) / 归入分类 / ✕；选中 0 时置灰。归入分类复用现有 Picker。
  • 详情页同步加一个「删除」（同一确认逻辑，本稿只画列表侧）。

删除语义（按来源区分，关键）

  • 自录场次：真删——音频文件（Music/voxnote 或私有目录）+ app-state 记录。不可恢复，确认框明说。
  • 厂商导入场次：删除 = 屏蔽该 sid（意图层 ignored 列表，落 app-state.json）。因为场次是从日志重放出来的，只删镜像会被下次扫描复活；厂商的 wav / 日志 / md 一律不碰。
  • 被屏蔽的场次不再进列表、不进筛选计数；设置页提供「已屏蔽 n 场 → 恢复」入口（对应"意图层可撤销"）。
  • 正在录音 / 正在播放中的场次：禁止删除（按钮禁用 + 提示）。
  • 删除会把 s1rec/sessions 镜像一并清掉；transcript.md 属导出物，随卡片消失、可重建。

实现落点（预估）

  • State.java：新增 ignored（sid 黑名单）与删除时清理 title/cat/marks。
  • CardRow/SwipeRow：⋯ 按钮 + 长按回调；批量模式改 bind()（显示 checkbox、禁用滑动手势与点击进详情）。
  • HomeActivity：顶栏「管理」、选择栏、底栏、确认框（复用 Picker/Dialog 风格）、toast。
  • Storage：新增 deleteOwn(blob)（m4a + 同目录无其他文件时清理）；插件侧 scan() 过滤 ignored。
