# 合理使用流程（目标形态）

> 2026-10-26。配合 [重设计准备](../设计/重设计准备.md) 阅读：本文画的是**重设计之后应该有**的使用流程，
> 不是现在的实现。想对照"现在实际怎么跑"，见 [现在的流程](现有流程.md)。
> 所有 mermaid 图可在 GitHub / Typora / Obsidian / mermaid.live 直接渲染。
>
> 一条原则贯穿全文：**库房、远程引擎、云这些角色对用户不可见**。用户只需要看到
> "录了 → 在转 → 能读了 → 更准了 → 改过的都还在"，不需要知道是谁在转。

## 1. 一张图看懂主线

```mermaid
flowchart LR
  subgraph PHONE [手机]
    R["按一下开始录音"] --> S["录音落盘<br/>本地立刻能读"]
    S --> Q["自动排队上传"]
  end
  subgraph HUB [库房 常开]
    Q --> H1["收下录音<br/>记录入库"]
    H1 --> H2["小模型快稿<br/>几秒到几十秒"]
  end
  subgraph POWER [算力 按需上线]
    H2 -. 可选升级 .-> W["远程强机模型<br/>精稿"]
    H2 -. 可选升级 .-> C["手机直连云 API<br/>云端稿"]
  end
  H2 --> READ["手机 / 控制台阅读"]
  W --> READ
  C --> READ
  READ --> EDIT["改名 / 分类 / 打点 / 逐句修订"]
  EDIT --> SYNC["一轮同步：两端一致"]
  READ --> FIND["搜索 / 导出"]
```

要点：**先出快稿保底，再按条件升级**。用户永远不用等"最强的那台机器开机"才能读。

## 2. 第一次使用：配对与就绪

```mermaid
flowchart TD
  A["打开 App"] --> B{"已经配过服务器吗？"}
  B -- 是 --> F["进入主界面"]
  B -- 否 --> C["扫码 / 手填地址 + 令牌"]
  C --> D{"连通测试"}
  D -- 失败 --> C2["显示人话原因<br/>地址不对 / 令牌过期 / 防火墙"] --> C
  D -- 成功 --> E{"引擎就绪吗？"}
  E -- 缺模型 --> E1["提示：去控制台下载<br/>或先用手机云兜底"]
  E -- 就绪 --> G["试转一条示例录音"]
  E1 --> E2["可以先跳过，继续本地录音"]
  E2 --> F
  G --> H["进入主界面"]
  F --> I["顶部同步条：全部已同步"]
  H --> I
```

要点：**允许跳过**。没有服务器也能录音和本地阅读，只是"暂不同步"；
不能因为配置没完成就把用户挡在门外。

## 3. 日常一条录音的完整时序

```mermaid
sequenceDiagram
  autonumber
  participant P as 手机
  participant H as 库房
  participant W as 强机引擎
  participant C as 云 ASR

  P->>P: 录音落盘，本地立即可读
  P->>H: 上传音频（幂等键：录音哈希）
  H-->>P: 已收下，排队转写
  H->>H: 小模型快稿（几秒）
  H-->>P: 变更通知：已转写（快稿）
  Note over P: 用户这时已经能读，不用等

  W->>H: 健康探测（在线 / 模型 / 空闲槽位）
  H->>W: 提交转写请求（音频或签名 URL）
  W-->>H: 返回「精稿」结果
  H->>H: 切换生效指针到精稿
  H-->>P: 变更通知：已转写（精稿）
  Note over P,H: 人工修订独立存放，换稿不丢

  opt 强机久不在线，或用户主动选云端
    P->>C: 直接调用云 API（或经库房代理）
    C-->>P: 云端稿
    P->>H: 回传「尝试」（带录音哈希）
    H->>H: 按质量与用户选择切生效指针
    H-->>P: 变更通知：已转写（云端）
  end
```

要点：三个转写来源产出的是**三份不可变的"尝试"**，记录的只是"哪一份生效"。
所以同时发生也不会互相覆盖，手机离线云转写回来也不打架。

## 4. 一条记录的一生（状态机）

```mermaid
stateDiagram-v2
  state "仅本机（已录）" as LocalOnly
  state "上传中" as Uploading
  state "已上传（待转写）" as Uploaded
  state "排队中" as Queued
  state "转写中 36%" as Transcribing
  state "已转写（快稿 · 可升级）" as QuickDraft
  state "已转写（精稿）" as Refined
  state "失败（原因 + 下一步）" as Failed
  state "已删除（墓碑）" as Deleted

  [*] --> LocalOnly: 录音完成
  LocalOnly --> Uploading: 自动上传
  Uploading --> Uploaded: 库房确认
  Uploading --> Failed: 上传失败
  Failed --> Uploading: 重试 / 换地址
  Uploaded --> Queued: 自动入队
  Queued --> Transcribing: 开始转写
  Transcribing --> QuickDraft: 快稿完成
  Transcribing --> Failed: 转写失败
  Failed --> Queued: 重试 / 换引擎 / 用云端
  QuickDraft --> Refined: 精稿升级
  Refined --> QuickDraft: 切回旧版（可对比）
  LocalOnly --> Deleted: 删除
  Uploaded --> Deleted: 删除
  QuickDraft --> Deleted: 删除
  Failed --> Deleted: 删除
  Deleted --> [*]
```

要点：对用户只暴露**一个状态**；失败一定有"下一步"；"更准的稿到了"是升级，不是状态回退。
用户也可以主动"钉住"某一版，不被自动升级覆盖。

## 5. 多端一致：改标题、删记录、改句子

```mermaid
sequenceDiagram
  autonumber
  participant P as 手机
  participant H as 库房
  participant W as 控制台

  P->>P: 改标题 / 改分类 / 打点 / 删一条
  P->>H: outbox 批量提交（每条带幂等 op_id）
  H->>H: 应用改动，rev + 1
  H-->>W: 变更流推送
  W-->>H: 改标签 / 逐句修订（只写人工层）
  H->>H: rev + 1
  H-->>P: 变更流：标题 / 标签 / 修订
  P->>P: 应用并更新本地库
  Note over P,W: 同字段两端同改：后到者胜，界面提示「已同步为最新」
  Note over P,W: 删除走墓碑：两端都消失，不会复活
```

要点：手机**先写本地再同步**，所以断网也能改；恢复后自动补上，不会丢也不会重复。
人工修订只写人工层，重转写永不覆盖。

## 6. 控制台里怎么整理

```mermaid
flowchart LR
  A["打开记录库"] --> B{"这次想干什么？"}
  B -- 处理积压 --> C["筛选：仅音频 / 失败 / 转写中"]
  B -- 找东西 --> D["搜索标题与全文"]
  C --> E["选中一条"]
  D --> E
  E --> F["右侧读稿 + 播放 + 点句跳播"]
  F --> G{"接下来？"}
  G -- 改内容 --> H["改标题 / 标签 / 逐句修订"]
  G -- 要更准 --> I["用更强引擎重转（生成新尝试）"]
  G -- 拿出去 --> J["导出 MD / SRT"]
  H --> K["自动保存并同步回手机"]
  I --> F
  J --> L["完成"]
```

要点：控制台的主线只有一件——**读和改**。队列状态长在列表上，不再单独一个"任务页"。

## 7. 失败时用户看到什么（统一失败卡）

```mermaid
flowchart TD
  A["任何一步失败"] --> B["失败卡：发生了什么 + 人话原因"]
  B --> C{"系统给出的下一步"}
  C -- 网络 / 服务器 --> C1["换地址 / 检查配对 / 稍后自动重试"]
  C -- 引擎未就绪 --> C2["去下载模型 / 换引擎 / 改用云端"]
  C -- 音频解码不了 --> C3["转成 16k wav 再试"]
  C -- 空间 / 权限 --> C4["清理空间 / 改存储位置"]
  C -- 没识别到语音 --> C5["确认不是静音 / 重新录"]
  C1 --> D["重试成功，回到主线"]
  C2 --> D
  C3 --> D
  C4 --> D
  C5 --> D
  D --> E["状态恢复：已转写 / 已同步"]
```

要点：所有失败共用一个卡片样式，永远包含"原因 + 动作"；
原始异常折叠起来给排查用，不直接甩给用户。

## 9. 入口对照表（谁在哪做什么）

| 用户想做的事 | 手机 | 控制台 | 说明 |
| --- | --- | --- | --- |
| 录一条 | 首页大按钮 | — | 录完自动入库 |
| 看同步/转写进度 | 顶部同步条 → 同步中心 | 记录库状态 + 活动中心 | 同一套状态词 |
| 读、改、打点 | 详情页 | 详情页 | 改完自动同步 |
| 要更准的稿 | 详情任务卡「用更准的重转」 | 记录详情「重新转写」 | 生成新尝试，可切回 |
| 配服务器 | 设置 → 服务器地址簿 | 设置 → 配对二维码 | 首次向导 |
| 看引擎/模型状态 | 只读 | 系统状态页 | 手机不猜 |
| 删记录 | 详情 / 批量 | 记录详情 | 墓碑，双向消失 |
| 找东西 | 搜索 | 搜索（全文） | 同一套筛选语义 |

## 10. 验收这组流程（5 个任务）

1. 新用户：扫码配对 → 引擎就绪 → 转出一条，≤3 分钟；
2. 断网：飞行模式录一条 → 恢复网络 → 自动上传并出稿；
3. 失败：故意让引擎不可用 → 用户能看懂原因并修好；
4. 一致：手机改标题、删一条 → 控制台刷新后一致，且不复活；
5. 多来源：手机云转一条 + 库房转一条 + 远程强机升级一条 → 三版共存、可切换、人工修订不丢。

全过 = 流程合理；任何一项卡住，回到对应图改路径，而不是加按钮。
