# 切换手册（v1 → v2，破坏性重建）

> 决策：**不迁移历史数据**。新版本从空库开始；旧数据库、旧录音、旧 md 原样保留。
> 目标：切换可执行、可验证、可回滚。

## 0. 前置

- 分支：`design/redesign-v1`（V1 全部改动在此）。
- 本机工具链（无需下载）：
  - JDK：`C:\Program Files\Android\openjdk\jdk-21.0.8`
  - SDK：`C:\Program Files (x86)\Android\android-sdk`
- 构建 APK：

```powershell
pwsh -NoProfile -File android\build.ps1 `
  -Toolchain 'C:\Program Files\Android\openjdk\jdk-21.0.8' `
  -Sdk 'C:\Program Files (x86)\Android\android-sdk'
# 输出：android/build/voxnote.apk
```

## 1. 备份（必须）

```powershell
# 服务端数据（旧库 + 音频 + 导出）
Compress-Archive -Path server\data -DestinationPath backup\server-data-$(Get-Date -Format yyyyMMdd-HHmm).zip
# 手机数据（按实际设备/目录）
adb pull /sdcard/s1rec backup\s1rec-$(Get-Date -Format yyyyMMdd-HHmm)
adb pull /sdcard/Android/data/dev.voxnote/files backup\voxnote-files-$(Get-Date -Format yyyyMMdd-HHmm)
```

> `backup/` 已在 `.gitignore`，不会进仓库。

## 2. 启动 v2

```powershell
cd server
venv\Scripts\python run.py
# 控制台：http://127.0.0.1:8787 （v2 默认；旧版在 /legacy）
```

- 首次启动会自动创建 `data/voxnote-v2.db` 与 `settings.sync_token`（`vn2-…`）。
- 旧 `data/voxnote.db` 不读、不改；旧音频文件也不动。
- 在控制台「存储与诊断 → 配对手机」扫码，手机自动填地址 + v2 令牌。
- 引擎：控制台「引擎」页添加 OpenAI 兼容地址（如强机上的 STT 服务）。

## 3. 验证（按顺序）

```powershell
python scripts\acceptance.py      # 5 个任务脚本：新用户/断网/失败/一致性/多来源
python scripts\restore_drill.py   # 备份恢复 + VOXNOTE_V2=0 回滚演练
python scripts\bench.py           # 1k 记录 / 1 小时音频预算
python -m unittest discover -s server\tests -v
```

手机端真机检查（需要设备）：

- 锁屏录音 10 分钟不中断（前台服务通知在）；
- 录音后列表出现、同步中心待上传归零；
- 详情页转写（确认云提示）→ 状态变已转写；
- 改名/分类/标记/删除双向一致；
- 冲突时同步中心能选本地/服务器；
- 导出 md/srt；自动连播开关生效。

## 4. 回滚

```powershell
# 停 v2，用旧版启动；旧库与旧文件未改动，直接可回
$env:VOXNOTE_V2=0
cd server; venv\Scripts\python run.py     # / 回到 v1 控制台
```

若 v2 本身出问题：停服务 → 用备份覆盖 `data/voxnote-v2.db`（或整目录恢复）→ 重启。

## 5. 已知边界（V1）

- 手机端引擎"新增/编辑"未做，用控制台配置；
- 冲突 UI 是两边 payload 文本，逐项 diff 后置；
- 队列失败不自动重试，用户可再次点转写；
- 真机冒烟未执行（无设备），见第 3 节清单。
